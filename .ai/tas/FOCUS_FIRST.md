# TEACHER AI STUDENT — фокус migration-first (решение 2026-11-11)

## Сначала рабочая основа, потом новый интерфейс

**Цель сейчас:** перенести данные существующей Google Sheets в PostgreSQL, поднять API/БД на сервере и подключить действующую преподавательскую форму `EGA/config/manage.html` через защищённый ASP.NET Core API.

**Не строить новую админку и интерактивные механики до работающего manage + PostgreSQL.** Присланные скриншоты — визуальные ориентиры для будущего кабинета, не требование их срочно копировать.

## Не персональная система

Платформа предназначена нескольким независимым преподавателям по **любым дисциплинам**: математика ЕГЭ/ОГЭ — только первый источник данных и пилот. Модель: workspace/teacher → ученики → предметы и курсы/программы → занятия, ДЗ, результаты, абонементы. Нужны server-side tenant isolation и teacher auth **до** выдачи данных из `manage`.

## Порядок поставки

1. **M01:** понять каждую таблицу и вызов manage; спроектировать tenant/subject/auth, закрыть ошибки данных.
2. **M02:** приватный сервер staging, API/PostgreSQL, миграции, health, backup/restore.
3. **M03:** импортировать историю по сущностям, dry-run/rehearsal и reconcile без потерь; не смешивать готовность импортёра с завершённым переносом.
4. **M04:** учительские read/write API и переключаемый адаптер текущей manage; E2E на двух synthetic tenant.
5. **M05:** backup, финальный delta-import, явно одобренный cutover с Sheets/GAS на PostgreSQL, мониторинг.
6. **M06:** постепенно построить удобную универсальную админку на том же API, по референсам пользователя.
7. **M07:** межпредметный банк задач, доска, шаблоны, AI и рекомендации. Предыдущий [lesson-mechanics-mvp.md](../../docs/architecture/lesson-mechanics-mvp.md) сохраняется как поздний черновик, а не NEXT_ACTION.

**Текущая задача:** `M01-01`. [Доска задач](./TASK_BOARD.md) и [чеклисты](./PHASE_CHECKLISTS.md) — источники порядка. Не восстанавливать старый P02-05 из прошлых чатов.

## Технические правила

Существующие `Platform.StudentImport` и `Platform.HomeworkImport` переиспользовать. Не импортировать реальные XLSX в Git. Проблемные строки источника показывать как blockers, не выдумывать значения. Пока staging/teacher auth/полная сверка не прошли, production по-прежнему использует GAS. В момент cutover должен остаться **один** writer, с планом дельты и восстановления. Права на данные принадлежат tenant, а не URL/переданному studentId.
