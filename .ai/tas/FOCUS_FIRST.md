# Фокус TAS: что делать прежде всего

## Что продаёт продукт

Не просто учёт занятий. **Учитель описывает теорию обычным языком → платформа собирает проверяемый интерактивный урок → ученик исследует идею на графике/модели → его действия записываются → следующая задача предлагается по данным, а не наугад.**

Примеры: параметр параболы и изменение её графика, геометрическая модель с управляемыми точками, дерево вероятностей с выбором исходов. Один шаблон должен работать на разных темах и наборах чисел.

## Первый проверяемый вертикальный срез (без смены ID из ROADMAP)

1. **P00-01:** выяснить, какие интерактивы, API и события уже существуют.
2. **P01-05 / P02-05:** согласовать 5–10 механик, `LessonDefinition` v1 и события.
3. **P08-01...P08-06:** переиспользуемый движок шаблонов, задачи, рендер и ответы.
4. **P07-01...P07-06:** живая комната с синхронной доской и восстановлением; использовать существующий runtime там, где он подходит.
5. **P12-01...P12-05:** LLM -> валидный LessonDefinition -> проверка учителем; куратор выбирает только реальные ID банка.
6. **P09-01...P09-05:** ДЗ с автооценкой проверяемых ответов и ручной проверкой развёрнутых решений.
7. **P10-01...P10-05:** измеримое состояние ученика, ошибки и результаты.
8. Затем интегрировать календарь, абонементы, мессенджеры и пилот по зависимостям.

Это **приоритет**, а не разрешение игнорировать безопасность, auth, tenant-границы и prerequisites фаз P03/P04. По каждой конкретной задаче сначала проверить gate-зависимости.

## Численно проверять две научные гипотезы

- Доля AI-сценариев, проходящих JSON-schema, и доля принятых преподавателем **без правок**.
- Точность прогноза следующего ответа BKT и изменение результата после рекомендованного задания в сравнении с базовым выбором.

Время на подготовку урока, создание ДЗ и проверку считать по реальным замерам; не выдавать презентационные цифры за подтверждённую экономию.
