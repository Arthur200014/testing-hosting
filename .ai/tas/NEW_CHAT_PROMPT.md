# Сообщение для нового чата

Скопируй блок ниже целиком. Он не требует заново прикреплять ТЗ.

```text
Продолжаем TEACHER AI STUDENT в моём GitHub-репозитории
Arthur200014/testing-hosting (ветка main). Это существующий рабочий
репозиторий; не создавай новый и не переделывай весь проект.

Прочитай AGENTS.md и .ai/START_HERE.md, затем
.ai/tas/HANDOFF.md и .ai/CONTEXT_MAP.md.
Твой NEXT_ACTION — ID из HANDOFF.md. Если я укажу другой task ID,
используй его, но сначала проверь зависимости.

В .ai/tas/TASK_BOARD.md и PHASE_CHECKLISTS.md открывай ТОЛЬКО
соответствующую задачу и раздел фазы. Учитывай текущие
.ai/tasks/ и docs/architecture/ для этой задачи.
Не читай рекурсивно весь репозиторий, весь EGA/OGA, все задачи
или старую историю. Найди точные файлы по путям и символам,
затем читай код и тесты только в рамках найденных зависимостей.

Работай с существующим кодом; не переписывай то, что уже проверено.
Вноси минимальные изменения локально в доступном git checkout или
через GitHub-инструменты, если локального checkout нет.
Не заявляй, что локально менял или тестировал, когда работал
только через GitHub API.

На одну задачу: выяснить цель и критерии готовности -> реализовать ->
запустить релевантные тесты -> проверить diff -> обновить
.ai/tas/TASK_BOARD.md, HANDOFF.md, TEST_RESULTS.md и нужную
.ai/tasks/<task>.md -> сделать commit и push в main по AGENTS.md.
Никакого force push, секретов, чужих изменений и опасного тестирования
на данных реальных учеников.

В конце ответь коротко:
TASK_ID; что сделал; какие файлы изменил; какие тесты прошли;
ссылка на коммит; PUSH_STATUS; один следующий NEXT_ACTION.
Если завершить не получилось — зафиксируй BLOCKED и точный блокер.
```

Для продолжения конкретной задачи можно дописать:
`Продолжи P08-03; на прошлой попытке остановились на ...`.
Но основной и более свежий источник правды — `.ai/tas/HANDOFF.md` в `main`.
