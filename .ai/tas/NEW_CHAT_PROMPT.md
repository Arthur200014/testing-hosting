# Запрос для нового чата

## Короткий вариант

Скопируй в новый чат с доступом к репозиторию:

`Продолжай по хандоффу в https://github.com/Arthur200014/testing-hosting на GPT-6.1 Sol Medium. Прочитай только AGENTS.md и .ai/tas/HANDOFF.md на main, затем файлы и 1–2 референса, названные в NEXT_ACTION. Ищи символы перед чтением больших файлов; не выводи в чат полные файлы, исходник сайта, дерево репозитория, диффы, логи или JSON. Реализуй один следующий рабочий сценарий, сделай только нужные проверки, commit/push и коротко обнови HANDOFF. Не удаляй учеников и доски, не меняй пароли и не повторяй импорт.`

## Если нужен полный запрос

`Продолжай TEACHER AI STUDENT в существующем репозитории https://github.com/Arthur200014/testing-hosting. Владелец хочет максимально точно воспроизвести доступный кабинет преподавателя Meleto, начиная с классов; собственные особенности позже. Не начинай проект с нуля и не делай повторную инвентаризацию всего репозитория.

Сначала прочитай AGENTS.md и .ai/tas/HANDOFF.md на main. Если ACTIVE_BRANCH указан, проверь её HEAD и продолжи незавершённую работу с её NEXT_STEP. Иначе реализуй NEXT_ACTION. Очередь — .ai/tas/RELEASE_PLAN.md, приёмка — PHASE_CHECKLISTS.md, навигация — .ai/CONTEXT_MAP.md. Старые Mxx/Pxx файлы исторические и не задают следующую задачу.

Работай в режиме экономии контекста. Рекомендуемая модель — GPT-6.1 Sol, reasoning Medium. Сначала ищи нужные символы/маршруты/селекторы, потом читай только ограниченные участки вокруг совпадений. Не загружай и не печатай целиком большие HTML/JS/C# файлы, исходник всего сайта, дерево репозитория, полный diff, логи, ответы API/БД или все тесты. Большой вывод обработай внутри инструмента, в чат верни только вывод и пути изменённых файлов. Не перечитывай неизменённое.

Для текущих экранов найди Meleto_Reference_Pack.zip в моей ChatGPT Library по ссылке из .ai/tas/MELETO_REFERENCE.md. Посмотри только 1–2 PNG и соответствующие JSON-записи нужных ID из MELETO_SCREEN_INDEX.md. Не открывай весь PDF и все 74 изображения. Если доступа к архиву нет, скажи, что нужно прикрепить ZIP; не утверждай совпадение дизайна без кадров. Не путай наблюдаемый интерфейс с проектной схемой БД из PDF.

Реализуй один сквозной сценарий на существующих .NET/PostgreSQL/API и синтетических данных: UI + реальное чтение/сохранение + права + ошибка/отмена + визуальная сверка. Не создавай статические кнопки, которые кажутся работающими. Не запускай полный набор тестов: начни с минимальной проверки изменённого поведения и расширяй только при ошибке или реальном риске. Не создавай агентов, новый план, повторный аудит или документацию без необходимости. После значимого этапа сделай commit/push и короткий HANDOFF: результат, изменённые пути, PASS/FAIL/NOT_RUN и один следующий шаг. Для долгой задачи используй одну рабочую ветку. Не удаляй учеников/доски, не меняй пароли, не повторяй импорт и не переключай текущий production writer без отдельного явного решения.`

Одной короткой фразы достаточно, если новый чат может читать репозиторий и пакет в Library. Если архив недоступен в этом чате, приложи [Meleto_Reference_Pack.zip](https://chatgpt.com/library?file_id=libfile_2a4feb1037c08191997ce235ce5fd686&account_id=personal).
