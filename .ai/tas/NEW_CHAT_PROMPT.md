# Инструкция для нового чата: TAS, выполнение с тестами по текущей задаче

Вставь следующий текст в новый чат. Документы уже хранятся в GitHub, повторные вложения не нужны.

```text
Продолжай разработку TEACHER AI STUDENT в репозитории
Arthur200014/testing-hosting. Не создавай новый репозиторий.

1. Сначала прочитай AGENTS.md и .ai/START_HERE.md.
Открой .ai/tas/HANDOFF.md на ветке main.
Если указан ACTIVE_BRANCH, восстанови именно её, прочитай
актуальный HANDOFF, карточку задачи и последний remote commit.
Если ветки нет — возьми NEXT_ACTION из HANDOFF на main.

2. Читай только нужную задачу из .ai/tas/TASK_BOARD.md,
нужную фазу из PHASE_CHECKLISTS.md, .ai/CONTEXT_MAP.md
и непосредственно связанные файлы кода/тестов.
Не читай весь репозиторий, все EGA/OGA или все 92 задачи.
Проверяй, что уже реализовано, чтобы не дублировать код.

3. ДО РЕАЛИЗАЦИИ создай/обнови карточку
.ai/tasks/tas-<TASK_ID>.md по .ai/tas/TASK_TEMPLATE.md.
Составь подробный чеклист маленьких шагов, точные пути файлов,
критерии приёмки и тест-кейсы ДЛЯ ЭТОЙ ЗАДАЧИ:
позитивные сценарии, неверные входные данные/ошибки,
важные граничные случаи и узкая регрессия существующей функции.
Укажи входные данные, ожидаемый результат и исполняемую
команду/способ проверки каждого кейса.
Сначала COMMIT+PUSH плана и подтверждение SHA на GitHub,
только затем изменяй исполняемый код.

4. РЕАЛИЗУЙ И ПРОВЕРЯЙ ПО ПУНКТАМ:
- Измени только код, нужный для текущей задачи.
- Вместе с ним напиши или обнови автоматические тесты именно
  новых/изменённых функций; не тестируй все страницы подряд.
- Запусти эти тесты реально: через локальный/изолированный
  runner или подходящий GitHub Actions workflow для нужного SHA.
- Если подходящего CI нет, добавь минимальную безопасную
  проверку для затронутого модуля, если можешь её выполнить.
- Для интерфейса проверь изменённые сценарии в браузере;
  для realtime — два клиента и reconnect, если задача их касается.
- При FAIL разберись в логах, исправь причину и снова запусти
  все тест-кейсы этой задачи плюс узкую регрессию.
- Только PASS по реально выполненной проверке позволяет
  отметить соответствующий пункт чеклиста [x].
- Не считай тест выполненным только по наличию YAML или кода.
  Если среда не позволяет тестировать, ставь BLOCKED/NOT_RUN,
  фиксируй причину и НЕ отмечай задачу DONE.

5. Для задач дольше 5 минут: следуй .ai/tas/CHECKPOINTS.md.
Работай в tas/<TASK_ID>, делай небольшие WIP-коммиты
и PUSH после этапов, ориентировочно каждые 3–5 минут.
Сохраняй чеклист, результаты проверок, точные изменённые файлы,
LAST_CHECKPOINT и NEXT_STEP в task-карточке и HANDOFF.
Непроверенное оставляй на task-ветке, не переноси в main.

6. По завершении проверь diff и отсутствие секретов,
подтверди успешный прогон применимых тестов для текущей задачи,
обнови TASK_BOARD, TEST_RESULTS, HANDOFF и карточку задачи.
Лишь после этого безопасно перенеси итог в main без force push,
сделай финальный COMMIT и PUSH, проверь SHA на GitHub.

Если задача прервалась, новый чат продолжает её с remote
checkpoint, а не начинает заново.

В конце кратко: TASK_ID, статус, что изменил, какие тест-кейсы
прошли/не прошли, где именно запускал, ссылка на run при наличии,
ссылка на commit, ACTIVE_BRANCH, LAST_CHECKPOINT и NEXT_STEP.

Начинай с текущего NEXT_ACTION. Не ограничивайся планированием,
после сохранения карточки приступай к работе и тестированию.
```
