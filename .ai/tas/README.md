# TEACHER AI STUDENT — работа в testing-hosting

**Основной репозиторий:** `Arthur200014/testing-hosting`, ветка `main`. Это проект внутри существующего репозитория, не отдельная GitHub-организация или новый репозиторий.

## За 30 секунд

1. Прочитай корневые `AGENTS.md` и `.ai/START_HERE.md`.
2. Прочитай **только** `HANDOFF.md`; в нём один `NEXT_ACTION`.
3. Открой соответствующую строку `TASK_BOARD.md` и раздел фазы в `PHASE_CHECKLISTS.md`. Не читай весь список.
4. Используй `.ai/CONTEXT_MAP.md` и целевой поиск файлов/символов. Прочитай лишь нужные исходники, зависимости и релевантные тесты.
5. Перед изменениями опиши точные критерии приёмки и допустимые пути; проверь реальный код. Старые файлы из `.ai/tasks/` могут содержать подтверждённые наработки.
6. Если задача долгая (>5 минут), создай/возобнови `tas/<TASK_ID>` и делай checkpoints после небольших этапов по `CHECKPOINTS.md`. Рабочую ветку и следующий шаг фиксируй в `HANDOFF.md`. В `main` переносится только проверенный финал.
7. В ответе укажи ID, изменённые файлы, тесты, hash коммита, PUSH_STATUS, NEXT_ACTION.

## Важно

- **Самый важный продуктовый сценарий:** преподаватель задаёт тему → LLM формирует валидный `LessonDefinition` → движок показывает интерактивное объяснение → ученик выполняет задания → ДЗ проверяется автоматически там, где ответ проверяем → модель знаний рекомендует следующий ресурс **из существующего банка**.
- Расписание, абонементы, карточки учеников, Telegram/MAX — поддерживающая часть продукта, а не главное научное отличие.
- Не делать вид, что все функции отсутствуют: в репозитории уже есть `platform/`, `shared/` и интерактивные страницы. Статусы нужно сверять с кодом и тестами.
- Не менять production/старые страницы, данные учеников, GAS, Firebase, ссылки без явно согласованной задачи.
- Когда работаешь **локально**: один раз `git clone`; затем `git fetch`, переход на актуальную ветку из HANDOFF, целевой поиск, тесты, commit/push. Не требуется каждый раз клонировать или читать все файлы.
- GitHub-коммит **не** равен автоматически проверенному развёртыванию на VPS.

- Новый чат/облачная среда не гарантирует доступ к локальным незакоммиченным файлам: восстанавливается только подтверждённый remote checkpoint.
