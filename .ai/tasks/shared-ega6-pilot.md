# Общие модули интерактивов EGA/6

Status: DONE

## Цель

Вынести повторяющуюся логику интерактивов из HTML в общие JS-модули, чтобы
исправления подключения, входа, отправки результатов и доски делались в одном
месте. Подготовить единый клиентский интерфейс для будущего ASP.NET Core API.

## Область работы

Первое подключение модулей — пара `EGA/6/что не так-1.html` и
`EGA/6/что не так-2.html`, выбранная за одинаковые функции и разные задания.
Действующие Firebase и Google Apps Script остаются рабочими поставщиками.

## Вне области работы

PostgreSQL, ASP.NET Core, Redis, SignalR, изменение игровых заданий,
интерфейса и публичных URL, массовый перенос других разделов.

## Текущее состояние

Десять realtime-страниц `EGA/6/` используют `realtime-lifecycle.js` для
инициализации Firebase, путей и подписок. Две страницы пилота дополнительно
используют `shared/v1/` для API, идентификации, очереди результатов,
транспорта, подписок занятия, доски и курсора. Игровые данные и правила
по-прежнему находятся в HTML. Остальные восемь страниц пока не перенесены.

## Принятые решения

- Использовать обычные ES-модули рядом со страницами и версионировать путь
  общего API при несовместимом изменении.
- Страницы сохраняют содержание игры и её правила. Сетевой клиент, учёт
  присутствия, очередь результатов, доска и курсор имеют отдельные границы.
- Проверка ученического кода пока использует GAS; будущий серверный API
  подключается через общий клиент. Браузер не обращается напрямую к PostgreSQL.
- Завершающая транзакция пилота использует `applyLocally:false`: исходная
  версия воспроизводимо прерывала её записью результата на 15-м шаге.
- Не считать описания таблиц и бизнес-правил из приложенного плана проверенными
  фактами; текущий шаг не переносит данные.

## Проверка

Обе страницы: локальный эмулятор RTDB, два клиента, вход ученика, рисование,
стирание, перезагрузка и повторный вход прошли на desktop и mobile. Полный
цикл 15/15 дошёл до `finished`; при заблокированном GAS результат попал в
очередь. Модульные проверки подтвердили дедупликацию, офлайн/повторную
отправку и реакцию подписок на переподключение. Production RTDB/GAS не
достигались; ошибки консоли только от намеренно заблокированных запросов.

## Открытые вопросы и риски

- Остальные восемь realtime-страниц отличаются схемами штрихов, событиями и
  порядком учёта присутствия; подключать их после проверки контрактов.
- Проверка кода учителя сейчас выполняется в браузере. Серверная авторизация
  появится вместе с ASP.NET Core, а не от одного лишь переноса JS-кода.
- Реальная запись в GAS намеренно не тестировалась; проверена постановка
  результата в очередь и локальная логика её повторной отправки.
- После `applyLocally:false` переход «Далее» при медленной сети может
  дольше показывать текущий вопрос, ожидая подтверждения RTDB.
