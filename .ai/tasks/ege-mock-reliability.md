# Надёжность форм пробников ЕГЭ и ОГЭ

Status: IN PROGRESS

## Цель

Сделать ученические формы `EGA/config/probnic.html` устойчивыми к перезагрузке,
повторному открытию и временному отсутствию сети. Для каждого активного пробника
ученик должен иметь только одну официальную сдачу, в том числе при входе с
другого устройства. Технические статусы транспорта ученику не показываются.

## Область работы

- ЕГЭ и ОГЭ в общей форме пробника.
- Локальный черновик, абсолютный таймер, результат и очередь отправки.
- Строгая серверная квитанция и повторная доставка.
- Проверка ранее созданной сдачи по `studentId + mockId + programId`.
- Один стабильный `eventId` для одного ученика и пробника на всех устройствах.
- Браузерные сценарии и итоговая сверка с листом `Пробники`.

## Принятые решения

- Общей политикой хранения и отправки владеет
  `shared/interactive/v1/mock-exam-persistence.js`; отдельного второго модуля
  для ОГЭ нет.
- Локальный ключ попытки в первую очередь использует пригласительный код. Это
  сохраняет ту же попытку до и после получения канонического `studentId`.
- Стабильный официальный `eventId` детерминирован по каноническому `studentId`,
  программе и активному пробнику. Поэтому вход по пригласительному коду и вход
  по `studentId` на разных устройствах создают один идентификатор, а существующий
  GAS дедуплицирует его внутри `ScriptLock`.
- При входе фоновая read-only проверка листа `Пробники` ищет точное совпадение
  `studentId + mockId + programId`. Найденная сдача блокирует экзамен и оставляет
  только понятное сообщение «Этот пробник уже сдан».
- Перед каждым POST та же проверка выполняется повторно. Если она недоступна,
  отправка не считается успешной: событие остаётся в outbox до следующей
  попытки. Это fail-closed поведение не создаёт второй официальный результат.
- Событие удаляется из outbox только после строгой квитанции с тем же `eventId`
  либо после подтверждённого точного совпадения существующей сдачи.
- Если фоновая авторизация ещё не получила канонический `studentId`, завершённая
  работа сначала сохраняется как локальное ожидающее событие. После восстановления
  связи модуль повторяет авторизацию, отправляет канонический `eventId` и только
  после квитанции удаляет ожидающее событие. Перезагрузка этот процесс не теряет.
- Ученик не видит статусы «на устройстве», «отправляется» и системные ошибки
  транспорта. Ответы и результат остаются локально доступными.
- Таймер хранится через абсолютное время начала; закрытие или перезагрузка
  страницы его не сбрасывают.

## Ограничение серверной части

Приложенный GAS дедуплицирует атомарно только по `eventId`; отдельного
серверного действия `lookupMockSubmission` в развёрнутом скрипте нет. Текущая
форма закрывает этот разрыв двумя совместимыми мерами: точным поиском строки в
листе и одинаковым детерминированным `eventId` на всех актуальных устройствах.
Старый закэшированный или намеренно изменённый клиент теоретически способен
отправить другой `eventId`. Абсолютная защита от такого клиента потребует
добавить в GAS атомарную уникальность по `studentId + mockId + programId` и
развернуть новую версию скрипта.
