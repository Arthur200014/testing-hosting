# Task-specific project memory

Each substantial workstream gets its own file, created from `_TEMPLATE.md`.
Examples of possible names are `realtime-core.md`, `postgres-migration.md`,
`interactive-templates.md`, and `student-session-cleanup.md`; create one only
when that workstream actually exists. Do not keep one global progress file.

At the start of a continuation, read only the relevant task file. Keep it short
enough to read at once, normally hundreds of words rather than thousands. Store
confirmed state, decisions, exact relevant paths, recent verification, and the
next action. Reference code instead of copying large code blocks, logs, diffs,
or conversations. Update it when meaningful state changes and mark it DONE when
finished; do not append an endless diary.
