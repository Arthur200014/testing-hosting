# ЕГЭ №8 — очередность ходов в совместном контроле

Status: DONE

## Цель

Исключить пропуски и преждевременную смену ученика при прохождении контроля «B» с двумя и более выбранными участниками.

## Область работы

Только `EGA/8/gaid.html`: смена хода, воспроизведение действий и синхронизация `state/nav` в Firebase RTDB.

## Вне области работы

Теория, задания, дизайн, адрес гайда, авторизация, другие ЕГЭ/ОГЭ, архитектура Firebase.

## Текущее состояние

В старом коде репликация кликов выполняла обработчики `__PVZ_CONTROL_ANSWERED__` и `__PVZ_CONTROL_NEXT_TURN__` на удалённом клиенте. При быстром обновлении `ownerClient` повторный клик «Далее» мог дополнительно переключить очередь. Действия реплицировались без проверки номера задачи, а `nav` записывался без версии.

## Принятые решения

- Ходы и результаты учитывает только реальный владелец во время локального, а не воспроизведённого действия.
- Ответ/следующий ход проверяют индекс задачи и факт записи ответа; `controlRevision` возрастает при изменениях.
- `nav` для контроля записывается транзакцией с проверкой `runId` и версии, старые снимки игнорируются.
- Ученик не может ответить на устаревший экран; при отрисовке нужного задания блокировка снимается.
- Очередь действий не блокируется преждевременно пришедшим «Далее»; действие сопоставляется с показанным номером.
- Список выбранных участников не ограничивается двумя.
