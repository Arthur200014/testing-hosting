# TAS: автоматическое обновление Timeweb

Источник: репозиторий Arthur200014/testing-hosting, ветка main.
Используется существующее приложение Timeweb App Platform с Dockerfile platform/Dockerfile и существующая управляемая PostgreSQL. Новых серверов и БД не создавать.

## Основной вариант — встроенный автодеплой Timeweb

Единожды откройте Timeweb → App Platform → действующее приложение → Настройки → Настройки деплоя → Редактировать.
Проверьте источник: GitHub-аккаунт (не «репозиторий по ссылке»), testing-hosting, ветка main.
Включите «Сборка по последнему выполненному коммиту» и сохраните. В дальнейшем Timeweb обновляет приложение при появлении новых коммитов в main без ручных команд.
Путь health-check для backend: /health/ready. Настройки приватного PostgreSQL и секреты не меняйте.

Включение этого переключателя нельзя подтвердить или выполнить с доступом только к GitHub. Для этого нужен доступ к панели Timeweb. Если автодеплой уже включён, ничего дополнительно настраивать не требуется.

Важно: Timeweb не поддерживает нативный автодеплой репозитория, подключённого по URL. Для этого случая можно использовать запасной вариант ниже.

## Запасной вариант — GitHub Actions → Timeweb API

Файл .github/workflows/timeweb-api-auto-deploy.yml уже подготовлен в GitHub. Он отключён по умолчанию. Чтобы один раз активировать его при подключении по URL, откройте в GitHub → Settings → Secrets and variables → Actions и добавьте:

- Repository secret TIMEWEB_API_TOKEN — отдельный API-токен Timeweb («API и Terraform»), с минимальными правами на приложение. Не отправляйте токен в чат и не храните в коде.
- Repository variable TIMEWEB_APP_ID — ID существующего Timeweb App Platform приложения, не сервера и не PostgreSQL.
- Repository variable TIMEWEB_DEPLOY_MODE — ровно api.

После единовременной настройки деплой запускается автоматически после успешного workflow «Homework import integration» на main. Перед запуском проверяются актуальность коммита, ветка приложения и отключенность нативного автодеплоя. Не запускаются импортёры и не меняется состав БД.

Не включайте одновременно два механизма. Если нативный автодеплой работает, не задавайте TIMEWEB_DEPLOY_MODE=api.

Ответ Timeweb HTTP 2xx значит только, что запуск принят; завершение проверяется в Timeweb → Деплой, а работоспособность — по /health/ready.

## Что уже автоматически обновляется

GitHub Pages уже автоматически деплоит main; успешный workflow «pages build and deployment» подтверждён через GitHub. Это отдельная публикация статических страниц и не гарантирует обновления контейнера Timeweb.

## Безопасность

- Обычный запуск контейнера применяет только ожидающие EF schema migrations через platform/scripts/runtime-entrypoint.sh; исторический импорт повторять не требуется.
- Данные и история остаются в управляемом PostgreSQL; при дальнейшем изменении схемы нужны резервные копии.
- Не переключать GAS/manage на PostgreSQL и не менять реальные данные автоматически.
