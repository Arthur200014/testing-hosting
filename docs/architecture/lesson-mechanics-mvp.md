# TAS — интерактивные механики урока, рабочая спецификация MVP

**Задача:** P01-05. **Версия решения:** 2026-11-11, v1 scope.
**Статус:** технический baseline для реализации; педагогический пилот и пользовательское принятие ещё NOT_RUN. Это не готовый Template Engine и не изменение legacy-страниц.

## Набор механик

Механика — отдельный переиспользуемый renderer со своими допустимыми параметрами и типом ответа. **Условия и числа — данные**, не новая копия JS/HTML на каждый урок.

| ID | Приоритет | Что делает ученик | Формат проверяемого ответа |
|---|---|---|---|
| `parameterGraph` | MVP | Двигает параметр `a`, исследует график/пересечения, определяет число корней | `number`, `pointSet` |
| `geometryDrag` | MVP | Перетаскивает точки в допустимых ограничениях и исследует длины/углы | `number` или `geometryState` по явным геометрическим инвариантам |
| `probabilityTree` | MVP | Выбирает исходы на дереве, объединяет пути и вычисляет вероятность | `pathSet` и `rational` |
| `intervalSign` | MVP | Отмечает нули, выколотые точки, знаки и конечное множество интервалов | `intervalSet` |
| `stepSequence` | MVP | Расставляет реальные математические преобразования в правильном порядке | `orderedStepIds` |
| `unitCircle` | Следующий срез | Выбирает корни/дуги на тригонометрической окружности | `angleSet` |
| `vectorPlane` | Следующий срез | Строит направленные векторы и их координаты на сетке | `vector`, `number` |
| `choiceGrid` | Следующий срез | Выбирает один или несколько вариантов с объяснением ошибки | `choiceIds` |

Первый демонстрационный урок — `parameterGraph` (парабола и сдвиг по `a`); следующие — `probabilityTree` и `intervalSign`. Не требовать разработки всех восьми движков перед первым проверяемым вертикальным срезом. Для `geometryDrag` и `stepSequence` допускается ручная оценка, если в ресурсе нет точных инвариантов/эталонных шагов.

## Форматы и проверка

- `number`/`rational`: каноническое число или несократимая дробь как строка. Точность/допуск задаёт **конкретная задача**, не общий скрытый epsilon.
- `intervalSet`: упорядоченный список интервалов с границами, флагами включения и отдельными исключёнными точками; математически равные объединения должны считаться одинаковыми.
- `pointSet`/`angleSet`/`pathSet`/`choiceIds`: множества канонических идентификаторов/значений, порядок не важен, если не задан явно.
- `orderedStepIds`: точный порядок заранее разрешённых математически корректных переходов; никакой проверки только по словам ответа.
- `geometryState`/`vector`: нормализованные координаты/отношения, проверка через явные ограничения и допуски из ресурса; произвольное положение мыши не является ответом.
- `freeText` и фото решения разрешены **только для ручной проверки** на этом этапе. Не начислять автоматические баллы за неподдерживаемый формат и не выдавать отсутствие ответа за ноль.

Все дроби/формулы отображаются через существующие безопасные средства математического рендера с LaTeX; нельзя выполнять JS из задания, `eval`, произвольный HTML или непроверенные формулы. Задача с некорректными параметрами отклоняется до публикации.

## Минимальные инструменты доски

Для первого урока: перо (цвет/толщина), ластик штрихов, отмена/возврат, страницы, явное подтверждение очистки, координатная сетка с квадратной клеткой, учительский курсор/указка. Обновление страницы и восстановление соединения не должны стирать уже подтверждённые действия. Использовать существующий `shared/interactive/v1/`; наличие файлов **не доказывает**, что весь этот список уже работает — поведение проверяется в P07.

## Граница LessonDefinition v1 (контракт оформляется в P02-05)

Каждый блок имеет `blockId`, `mechanicId`, `resourceId` (из разрешённого банка), `promptLatex`, `params`, `answerSpec` и `rubric`. Сам урок имеет `schemaVersion`, `lessonId`, `title` и упорядоченные `blocks`. Ни teacher/student identity, ни API secrets в определении урока не хранятся. AI предлагает только параметры уже разрешённой механики и существующие `resourceId`; перед публикацией учитель видит предпросмотр и подтверждает.

Планируемые события: `block.opened`, `interaction.updated` (дедупликация/ограничение частоты), `answer.submitted`, `attempt.scored`; идентичность ученика выводится сервером из активной сессии, `eventId` нужен для идемпотентности. Это **дизайн**, не заявление, что API событий уже реализовано.

## Критерии первого реализованного среза

1. Один renderer принимает два разных `parameterGraph` ресурса **без изменения JS/HTML**.
2. Значение слайдера меняет именно соответствующую математическую модель, клетка на графике квадратная, ограничения параметра соблюдены.
3. Валидный ответ проходит, неверный остаётся неверным, повреждённое определение отвергается без выполнения кода.
4. Сохранённая попытка возвращает корректный `eventId`, отсутствие данных отличается от нулевого результата.
5. Только после изолированной проверки подключать записи новой платформы; legacy GAS/Firebase и действующие URL не переключать.
