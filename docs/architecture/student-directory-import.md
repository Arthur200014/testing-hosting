# Безопасный импорт справочника учеников

## Назначение и границы

`Platform.StudentImport` — отдельный локальный CLI для первого переноса листа
`Ученики` из XLSX в PostgreSQL. Он не является постоянным API сайта, не читает
Google Sheets по сети и не переключает существующие интерактивы с Google Apps
Script или Firebase.

Исходный XLSX и реальный program map должны находиться вне репозитория. CLI
читает только лист `Ученики`; остальные листы требуют собственной модели данных
и отдельных этапов миграции.

## Модель данных

- `Student` хранит отображаемое имя и активность ученика.
- `WorkspaceStudentMembership` связывает ученика с workspace и программой,
  хранит import identity и только HMAC-SHA256 кода входа.
- `LearningProgram` принадлежит workspace; составной foreign key не позволяет
  связать membership с программой другого workspace.
- `StudentImportBatch` хранит только технические digest и агрегированные
  счётчики, без имён, открытых кодов и внешних идентификаторов учеников.

Поля `grade`, `groupId`, `targetScore`, `notes`, `parentName` и `targetGrade`
проверяются по типу, но пока не сохраняются: для них требуется отдельное решение
по предметной модели и доступу к персональным данным.

## Контракт импорта

Без `--apply` выполняется `dry-run`. Он открывает repeatable-read транзакцию,
переводит её в PostgreSQL `READ ONLY`, строит план и откатывает транзакцию.
Отчёт содержит только агрегаты и диагностику вида «номер строки / поле /
категория».

`--apply` сначала валидирует весь снимок, затем одной serializable-транзакцией
создаёт необходимые workspace, программы, учеников, memberships и запись batch.
Ошибка или конфликт блокирует весь набор. Совпавший повтор не создаёт данные
повторно, расхождение существующей записи не перезаписывается скрыто, а ученики,
отсутствующие в новом снимке, автоматически не деактивируются. Конкурентный
повтор ограниченно повторяется после PostgreSQL serialization/unique conflict.

XLSX и program map читаются каждый в один ограниченный по размеру snapshot.
Digest и parser используют одни и те же bytes, поэтому журнал не может получить
hash другой версии файла при его одновременной замене.

## Проверенные свойства

Интеграционные тесты выполняются на настоящем PostgreSQL 17 и проверяют:

- отсутствие записей при `dry-run`;
- HMAC-only хранение кода и совместимость с student-session exchange;
- обычный и конкурентный идемпотентный повтор;
- блокировку дублей, неизвестных программ и расхождений;
- полный rollback при ошибке БД;
- сохранение активного ученика, отсутствующего в следующем снимке;
- отсутствие исходных значений в batch и безопасных diagnostics.

Команды сборки, тестов и локального запуска находятся в `platform/README.md`.
Production import, создание production mapping и переключение клиентов остаются
отдельными операциями после приватного `dry-run`, сверки и плана отката.
