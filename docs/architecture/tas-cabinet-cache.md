# Запуск кабинетов и кэш TAS

При загрузке преподаватель и ученик видят нейтральный экран, пока тот же сервер проверяет cookie. Действующая сессия открывает кабинет. Ответ об отсутствии сессии открывает форму входа. При сетевой ошибке экран предлагает повторить проверку. Преподаватель возвращается в сохранённый раздел, класс или занятие после проверки доступа. В sessionStorage сохраняется только позиция внутри кабинета.

PostgreSQL хранит сессии, роли, классы, задания и доски. API проверяет права до обращения к кэшу. Отзыв доступа действует через обычную проверку PostgreSQL.

Redis хранит результаты повторяющихся чтений справочников. Первый подключённый справочник — список активных программ преподавателя. Ключ включает идентификатор рабочей области и версию формата. Запись живёт 30 секунд. При сетевом сбое API читает PostgreSQL и ждёт 10 секунд перед новой попыткой обратиться к Redis. Некорректная запись обновляется из PostgreSQL. Схема и формат JSON сохраняются. Для каждого нового справочника нужно определить допустимую давность данных и правила сброса кэша при записи.

## Рабочий Timeweb

1. Используйте управляемый Valkey в приватной сети работающего App Platform. Адрес и поддерживаемый режим TLS берутся из вкладки «Подключение» кластера. Проверьте сетевую доступность от приложения перед изменением его сети. [Подключение Valkey в Timeweb](https://timeweb.cloud/docs/dbaas/valkey/connect-to-database).
2. В переменных существующего приложения задайте `Redis__ConnectionString` в [формате StackExchange.Redis](https://github.com/StackExchange/StackExchange.Redis/blob/main/docs/Configuration.md). Пример с TLS: `host:port,user=default,password=<секрет>,ssl=true`. Используйте имя узла из параметров TLS провайдера. Сохраните учётные данные только в настройках приложения.
3. После деплоя сделайте два запроса `GET /api/v1/teacher/programs` в течение 30 секунд с одним тестовым преподавателем. Заголовок ответа `X-TAS-Cache` показывает состояние запроса.

| Значение | Что произошло |
| --- | --- |
| `miss` | API прочитал PostgreSQL и успешно заполнил Redis. |
| `hit` | API вернул значение из Redis. |
| `disabled` | У приложения отсутствует настройка Redis. |
| `fallback` | Redis недоступен или ещё действует пауза после ошибки. API вернул данные из PostgreSQL. |

Для отката уберите переменную Redis и повторно разверните приложение. Данные в PostgreSQL доступны на всех этапах. Профиль `test` проверяет первый и повторный запросы, разделение рабочих областей, чтение без Redis, сетевой сбой и восстановление повреждённой записи.
